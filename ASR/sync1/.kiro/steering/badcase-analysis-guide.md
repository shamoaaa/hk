# Badcase 分析指南

## 概述

本指南帮助 Kiro 分析 ASR 模型的 badcase（识别错误样本），识别错误模式，并生成针对性的优化建议。

## 数据获取

运行结果分析脚本：

```bash
python scripts/analyze_results.py --model-path <model_path> --test-set <test_set_path>
```

输出 JSON 结构包含：
- `summary`：badcase 总数和按场景分布
- `error_type_distribution`：替换/插入/删除错误计数
- `top_badcases_by_cer`：CER 最高的 badcase 列表
- `pattern_analysis`：按场景的平均 CER 和错误类型分布

## 分析维度

### 1. 场景维度分析

按场景类型（纯净语音、背景人声、背景噪声）分析 badcase 分布：

| 场景 | 正常 CER 范围 | 关注阈值 |
|------|-------------|---------|
| 纯净语音（clean） | 2%-5% | > 8% |
| 背景人声（background_voice） | 8%-15% | > 20% |
| 背景噪声（background_noise） | 5%-10% | > 15% |

如果背景人声场景 CER 显著高于其他场景，重点分析该场景的错误模式。

### 2. 错误类型分析

三种错误类型的分析要点：

**替换错误（Substitution）**：
- 检查是否存在同音字/近音字替换模式
- 检查是否与特定声学环境相关
- 建议：热词表纠正、语言模型增强

**插入错误（Insertion）**：
- 检查是否在语音停顿处产生多余识别
- 检查是否与背景噪声相关
- 建议：调整 VAD 参数、后处理过滤

**删除错误（Deletion）**：
- 检查是否在语速较快时丢失字符
- 检查 badcase 是否集中在句末（可能与端点检测相关）
- 建议：数据增强（reverb 增强室内环境鲁棒性）、模型注意力机制优化

### 3. 错误模式识别

常见错误模式：

1. **同音字混淆**：如"好"→"号"、"已经"→"以经"
   - 解决方案：热词表、语言模型重排序

2. **背景人声干扰**：目标语音被背景人声覆盖
   - 解决方案：语音增强前端、SeACo 参数调整、数据增强

3. **尾部截断**：句末字符被删除
   - 解决方案：调整端点检测参数、增加训练数据多样性

4. **数字/专有名词错误**：数字和专有名词识别率低
   - 解决方案：热词表、领域数据增强

### 4. 高 CER 样本深度分析

对 CER 最高的 badcase 进行逐一分析：
- 对比参考文本和识别文本的差异
- 标注每个错误的类型和位置
- 识别错误模式（同音字替换、插入无关内容、删除句末等）

## 建议生成规则

### 模型维度
- 如果背景人声场景 CER > 纯净语音 CER × 3：建议添加语音增强前端
- 如果替换错误占比 > 60%：建议调整 SeACo 注意力权重

### 数据维度
- 如果某场景 badcase 占比 > 50%：建议对该场景进行数据增强
- 如果删除错误集中在短句：建议增加短句训练数据

### 后处理维度
- 如果存在高频同音字替换：生成热词纠正规则
- 如果存在规律性格式错误：生成正则替换规则

## 输出格式

Badcase 分析报告应包含：
1. **错误模式总结**：主要错误模式及其频率
2. **场景分析**：各场景的 CER 对比和主要问题
3. **优化建议**：按优先级排序的具体建议
4. **热词/正则规则**：可直接应用的后处理规则（如适用）
