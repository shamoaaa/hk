# 训练过程分析指南

## 概述

本指南帮助 Kiro 分析 ASR 模型训练过程中的指标数据，识别训练异常，并生成针对性的诊断报告和优化建议。

## 数据获取

训练指标在训练过程中实时写入 `logs/training/training_metrics.jsonl`。运行分析脚本：

```bash
python scripts/collect_metrics.py --log-dir logs/training/
```

输出 JSON 结构包含：
- `metrics_summary`：每个 epoch 的平均 CER/WER
- `training_curves`：loss 曲线、CER/WER 曲线、学习率曲线
- `alerts`：训练告警信息（停滞、NaN/Inf）
- `total_steps` / `total_epochs`：训练进度

## 分析维度

### 1. Loss 趋势分析

**正常模式**：
- 训练 loss 持续下降，验证 loss 同步下降
- 下降速率逐渐减缓但未完全停滞

**异常模式及诊断**：

| 模式 | 可能原因 | 建议操作 |
|------|---------|---------|
| Loss 不下降（停滞） | 学习率过小、陷入局部最优 | 提高学习率、增加 warmup、切换调度策略 |
| Loss 震荡 | 学习率过大、batch size 过小 | 降低学习率、增大 batch size |
| 训练 loss 下降但验证 loss 上升 | 过拟合 | 增加正则化、数据增强、减小模型容量 |
| Loss 出现 NaN/Inf | 梯度爆炸、数值不稳定 | 降低学习率、增加梯度裁剪、检查数据 |
| Loss 突然跳升 | 数据异常、学习率调度问题 | 检查数据批次、调整调度策略 |

### 2. CER/WER 趋势分析

- 关注 CER 的绝对值和变化趋势
- 对比不同 epoch 的 CER 改善幅度
- 如果 CER 改善速度明显放缓，考虑调整优化策略

### 3. 学习率调度分析

- 检查学习率是否在合理范围内（通常 1e-6 到 1e-3）
- 验证 warmup 阶段是否正常完成
- 确认调度策略是否与训练阶段匹配

### 4. 梯度范数分析

- 正常范围：0.1 到 10.0
- 梯度范数持续增大可能预示梯度爆炸
- 梯度范数过小（< 1e-4）可能表示训练停滞

## 告警处理

### 训练停滞告警（STAGNATION）

当连续 5 个 epoch loss 下降量均小于阈值时触发。

诊断步骤：
1. 检查当前学习率是否过小（< 1e-6）
2. 检查梯度范数是否过小（< 1e-4）
3. 检查验证 loss 是否同步停滞
4. 检查 batch size 是否过大

### 数值异常告警（NAN_INF）

当 loss 出现 NaN 或 Inf 值时触发。

诊断步骤：
1. 检查最近的学习率变化
2. 检查梯度范数历史
3. 检查是否有异常数据批次
4. 建议降低学习率并增加梯度裁剪

## 输出格式

诊断报告应包含：
1. **问题描述**：简明描述发现的问题
2. **可能原因**：列出最可能的原因（按可能性排序）
3. **建议操作**：具体的参数调整建议（包含具体数值）
4. **优先级**：1-5 级，5 为最高
5. **置信度**：0.0-1.0，基于数据支撑程度
