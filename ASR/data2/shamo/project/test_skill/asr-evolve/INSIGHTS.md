# Insights — 持久化的优化洞察

> 跨实验验证的可靠结论。

## 记录

### [2026-07-09] Baseline CER=15.55%，插入错误占30%是首要瓶颈
- 证据: baseline_v1 (node-1)，无增强原始数据训练，错误分布 Sub=39%/Ins=30%/Del=31%
- 适用条件: 当前数据集（300 条测试集）+ SeaCo-Paraformer large
- 应用方式: 插入错误主要来自背景人声被误识别（∅→'你','好','闭'等），增强训练中 speaker_mix 应优先调优；删除错误（'我'→∅,'的'→∅）提示模型对低 SNR 语音识别能力不足

### [2026-07-09] 完整增强链有效降低插入错误，但引发删除错误上升
- 证据: augment_v1 (node-2)，CER 15.55%→14.63%(-0.92%), Ins 30%→25%, Del 31%→39%
- 适用条件: speaker_mix SNR=[-3,15] + 完整增强链, augment_factor=1
- 应用方式: 增强训练能降低插入错误（背景人声区分能力提升），但模型对短词变保守导致删除上升。下一步应考虑：(1)缩小speaker_mix的SNR范围避免过度压制 (2)增加speed_perturb范围帮助短词识别 (3)热词优化提升召回

### [2026-07-09] SNR下界提高+speed扩范围+epoch翻倍：CER边际改善，召回显著提升
- 证据: augment_v2 (node-3), CER 14.63%→14.52%(-0.11%), 召回 78.33%→80%(+1.67%), Ins 25%→22%, Del 39%→44%
- 适用条件: speaker_mix SNR=[0,15], speed=[0.85,1.15], epoch=10
- 应用方式: 提高SNR下界有效减少插入(背景人压制效果)，但删除错误持续恶化(44%)。模型在增强数据上学到了"抑制非目标声音"的能力，但副作用是对弱信号短词也误抑制。下一步需要从训练策略上解决(如解冻seaco_decoder/热词层以增强短词激活，或减少volume_perturb的衰减范围)

### [2026-07-09] 热词优化对当前模型无效
- 证据: v0.2.1 与 v0.2.0 评估结果完全相同（CER/召回/逐条相同）
- 适用条件: augment_v1 模型 + 添加窗帘/空调/主灯/油价/监控热词
- 应用方式: 当前模型的错误主要来自声学层面（背景人声干扰+短词漏识别），热词解码层面无法解决。热词优化在声学问题解决后再验证

### [2026-07-10] 解冻seaco_decoder在当前配置下无效
- 证据: unfreeze_seaco_v1 (node-4), CER=14.52%/召回=80%，与node-3完全相同
- 适用条件: lr=1e-4, epoch=10, 增强数据5000条, freeze=hotword_only
- 应用方式: seaco_decoder解冻后在当前lr下可能变化太小难以体现。删除错误的根因不是冻结策略，而可能是增强数据中目标词信号本身被过度混淆。下一步应考虑：减小增强强度（增大原始数据比例）或降低lr让模型更精细学习

### [2026-07-10] lr=5e-5(降半)导致退化，当前配置lr=1e-4是更优选择
- 证据: lr5e5_ep15 (node-5), CER 14.52%→14.90%(+0.38%), 召回80%→78%(-2%)
- 适用条件: 5000条增强数据, epoch=15, freeze=hotword+seaco
- 应用方式: lr=1e-4在当前数据量(5000条)下是合适的学习率，降低反而欠拟合。lr方向不是解决删除错误的路径。training_recipe类别连续2次无效(node-4/5)，应回到augmentation方向

### [2026-07-10] 精简增强链（去clipping+noise）带来最大单轮CER改善(-0.92%)
- 证据: slim_chain_v1 (node-6), CER 14.52%→13.60%(-0.92%), 召回80%→79.67%(基本持平)
- 适用条件: 增强链=reverb+speaker_mix+speed+EQ+volume, 关闭gaussian_noise+clipping
- 应用方式: clipping和gaussian_noise属于"非核心失真"，对智能家居场景贡献有限但增加了训练负担，让模型过度学习噪声应对而牺牲目标词识别。精简链让模型更专注于核心任务（区分目标/背景人声）。augmentation类别3/3有效，training_recipe 0/3无效——增强方向是唯一有效路径

### [2026-07-10] augment run CLI存在远程退出码误判bug
- 证据: 远程执行RC=0但CLI报Exit Code: 1。直接python调用RemoteExecutor执行成功
- 适用条件: 新namespace的增强（缓存miss时不影响，因为实际是直接复用的情况更多）
- 应用方式: 遇到augment run失败时，用debug脚本直接远程执行+手动merge即可绕过
