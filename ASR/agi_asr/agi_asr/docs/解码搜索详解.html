路径A CTC-Attention 联合 BeamSearch
nbest_hyps = self.beam_search( x=x, # 编码器输出 [T_i, D]，供 CTC scorer 使用 am_scores=am_scores, # SeACo 解码器输出 [N_i, Vocab]，作为 Attention 得分 maxlenratio=0.0, # 最大长度比（0=不限制，用 end_detect 自动停止） minlenratio=0.0 # 最小长度比（0=不限制） ) nbest_hyps = nbest_hyps[:self.nbest] # 取 top-1（nbest=1）
BeamSearchPara.forward() 内部流程：
  1. 初始化：创建初始假设 running_hyps = [Hypothesis(yseq=[sos], score=0)]
  2. 逐步搜索（for i in range(maxlen)，maxlen = N_token）：
    • 对每个假设，用 am_scores[i] 作为 Attention decoder 的得分（非自回归特性：不需要逐步调 decoder，得分已预计算）
    • 用 CTCPrefixScorer 计算 CTC 前缀得分
    • 用 LengthBonus 计算长度惩罚
    • 加权融合：score = 0.5 × ctc_score + 0.5 × attention_score + 0.0 × lm_score + penalty
    • 保留 top-K 假设（beam_size=10）
  3. 结束检测：当假设以 eos 结尾时移入 ended_hyps，或触发 end_detect
  4. 排序输出：按总分降序排列，返回 N-best 列表
💡 关键点：Paraformer 是非自回归模型，am_scores 已经一次性输出了所有 token 位置的概率分布。 BeamSearchPara 不需要像自回归模型那样每步调 decoder，它只是在已有的 am_scores 上做 CTC 重打分和剪枝。 这使得 beam search 的计算量远小于自回归模型。
路径 B · FST 热词 CTC Prefix Beam Search（本项目未启用）
路径B ContextGraph + CTC Prefix Beam Search + 热词打分
整体思路：
在标准 CTC prefix beam search 基础上，额外维护一个热词状态机（ContextGraph），对匹配热词的路径给予额外加分。
逐步流程：
  1. 构建热词图：context_graph = ContextGraph(self.hotword_list)
    基于字典（非 WFST）实现的前缀树，每个节点存储热词匹配状态和得分
  2. 初始化假设：
    cur_hyps = [(tuple(), (0.0, -float('inf'), 0, 0.0))] # prefix pb pnb c_state c_score # 空前缀 blank概率 非blank概率 热词状态 热词得分
  3. 逐帧搜索（for t in range(N_token)）：
    对每一帧 am_scores[t]（词表大小的 log 概率向量）：
    1. First beam prune：取 top-10 候选 token（logp.topk(beam_size)）
    2. 对每个候选 token s，遍历当前所有假设 cur_hyps：
      s == 0（blank）
      前缀不变，更新 blank 概率：
      pb = log_add(pb + ps, pnb + ps)
      热词状态和得分不变
      s != 0（非 blank）
      扩展前缀：n_prefix = prefix + (s,)
      查询热词状态机：
      new_c_state, new_c_score = context_graph.find_next_state(c_state, s)
      更新非 blank 概率 + 累加热词得分
    3. Second beam prune：按 log_add(pb, pnb) + c_score 排序，保留 top-10
      注意：排序时热词得分 c_score 直接加到声学得分上，使匹配热词的路径获得额外加分
  4. 输出：取最优假设的 token 序列，过滤掉 blank(0)、eos(2)、unk(8403)
⚠️ 注意：代码中 elif s == last（重复 token 处理）被注释掉了。 标准 CTC prefix beam search 需要区分"重复 token"和"blank 分隔的相同 token"， 但这里简化为所有非 blank token 都直接扩展前缀。这可能导致重复字符的处理不够精确， 但对中文场景影响较小（中文很少有连续相同字符）。
热词打分示例：
# 假设热词列表包含 "萤石" → token IDs [7891, 6502] # ContextGraph 内部是一个前缀树： # root --7891--> node1 (score=0.5) --6502--> node2 (score=1.0) # # 当解码路径产生 token 7891 时： # c_state: 0 → 1, c_score += 0.5 # 当接着产生 token 6502 时： # c_state: 1 → 2, c_score += 1.0 # 总热词加分 = 1.5，使 "萤石" 路径在排序时更靠前
路径 C · 贪心解码
路径C Argmax 贪心解码
最简单的解码方式，不做搜索，直接取每个位置概率最大的 token：
yseq = am_scores.argmax(dim=-1) # [N_i] 每帧取最大概率的token ID score = am_scores.max(dim=-1)[0] # [N_i] 对应的概率值 score = torch.sum(score, dim=-1) # 标量，所有帧概率之和 yseq = [sos] + yseq.tolist() + [eos] # 首尾加 sos/eos nbest_hyps = [Hypothesis(yseq=yseq, score=score)]
优点：速度最快，无搜索开销。缺点：无法利用 CTC 约束和语言模型，准确率最低。
适用场景：ctc_weight=0 且无 LM 且未启用 FST 热词搜索时的 fallback。
