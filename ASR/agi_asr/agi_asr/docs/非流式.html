EzvizModelBackend.forward() 非流式推理流程

asr/ezviz_backend.py → asr/funasr/bin/asr_inference_paraformer_vad_tp.py → SeacoParaformer

阶段一 · 请求入口与参数校验
入口 EzvizModelBackend.forward(rqs_info, rsp_msg)
HTTP 请求经 MS_Manager 框架路由到 /process 接口，调用此方法。
📄 asr/ezviz_backend.py : 168
校验 入参检查
  • 检查 data_info 长度必须为 1
  • 检查 modal 必须为 "audio"，type 必须为 "base64" 或 "url"
  • 任一不满足 → 返回 InvalidParamError，流程终止
热词 热词列表合并
将默认热词 ["萤石"] 与请求中传入的自定义热词合并，写入 self.param_dict['hotword']。
若请求未携带热词，则仅使用默认热词。
阶段二 · 音频解码
解码 音频数据解码与格式适配
根据 type 字段分支处理：
  • base64 → base64_decode() 解码为 PCM bytes → 封装为 [bytes, "speech", "bytes", "id1"]
  • url → .pcm → 直接读取文件二进制 → 同上
  • url → .wav/.opus → torchaudio.load() 加载为 waveform numpy 数组 → 封装为 [ndarray, "speech", "waveform", "id1"]
    若采样率 ≠ 16000，记录 infer_fs 用于后续重采样
  • url → .aac → pydub.AudioSegment 解码 → 转 float32 numpy → 同上
输出：data_path_and_name_and_type（统一格式的音频数据）+ infer_fs（采样率信息）
data_path_and_name_and_type, param_dict, infer_fs — 统一格式的音频数据 + 热词参数 + 采样率信息
阶段三 · 推理 Pipeline（inference_tp._forward）
Pipeline self.inference_offline() → _forward 闭包
调用 inference_tp 初始化时返回的 _forward 闭包，进入推理主流程。
📄 asr/funasr/bin/asr_inference_paraformer_vad_tp.py : 556
热词 热词列表生成 — generate_hotwords_list()
将字符串热词列表转换为 token ID 序列：
  • 每个热词 → 小写 → 正则过滤（去除长数字串、特殊编码）→ 中英文加空格分词
  • 若有 seg_dict（分词词典），进一步做子词分词
  • 通过 TokenIDConverter.tokens2ids() 转为 token ID 列表
  • 过滤：单个热词 ≤ 10 token，总数 ≤ 500 个
  • 末尾追加 [sos] 作为哨兵
输出：hotword_list = [[id1, id2, ...], [id3, id4, ...], ..., [sos]]
数据 构建数据迭代器 — ASRTask.build_streaming_iterator()
将音频数据封装为 PyTorch DataLoader：
  • bytes 类型 → load_bytes() 转 int16 → float32 归一化
  • waveform 类型 → 直接使用 numpy 数组
  • 若 infer_fs 不为 None → 执行重采样到 16kHz
  • 通过 collate_fn 做 padding，输出 batch = {speech: Tensor, speech_lengths: Tensor}
batch = {speech, speech_lengths} — 音频张量 + 长度，已 padding 对齐
阶段四 · 模型推理（Speech2Text.__call__）
前端 WavFrontend — 声学特征提取（两条路径）
根据 eable_vad 参数选择不同的前端处理路径：
eable_vad = False → forward()（完整流程）
输入：原始波形 waveform
  1. 波形 × 215 放大（int16 量化范围）
  2. kaldi.fbank()：80 维 Mel 滤波器组，25ms 帧长，10ms 帧移，Hamming 窗
  3. apply_lfr()：低帧率（LFR）特征拼接，连续 m 帧拼为一帧（m=7, n=6）→ 560 维
  4. apply_cmvn()：倒谱均值方差归一化（从 am.mvn 加载统计量）
本项目非流式推理走此路径（默认 eable_vad=False）
eable_vad = True → forward_lfr_cmvn()（半程流程）
输入：已提取的 FBank 特征（由 VAD 模块预先计算）
  1. FBank 提取（跳过，VAD 已完成）
  2. apply_lfr()：LFR 拼帧
  3. apply_cmvn()：CMVN 归一化
当 VAD 已对音频做过 FBank 提取时使用，避免重复计算
输出：feats [B, T', 560]，feats_len [B]
📄 asr/funasr/models/frontend/wav_frontend.py : 118 (forward) / 186 (forward_lfr_cmvn)
feats [B, T', 560] — 归一化后的声学特征（B=批次, T'=帧数, 560=80维FBank×7帧LFR拼接）
编码器 SeacoParaformer.encode() — 编码器前向
SANM（Self-Attention with Non-linear Memory）编码器：
  • 输入嵌入 + 位置编码
  • 多层 SANM Encoder Layer（Self-Attention + FeedForward + FSMN Memory）
  • 子采样（Conv2D 4倍下采样）
输出：enc [B, T'', D_enc]，enc_len [B]
📄 asr/funasr/models/e2e_asr_paraformer.py : 269 (Paraformer.encode)
enc [B, T'', D_enc] — 编码器输出（T''=下采样后帧数, D_enc=编码器隐层维度）
CIF calc_predictor() — CIF 预测器
Continuous Integrate-and-Fire（CIF）机制，预测输出 token 数量和声学嵌入：
  • 对编码器输出逐帧计算发射概率 alphas [B, T'']
  • 累积 alpha 值，当累积值 ≥ 1.0 时触发一次"发射"（peak）
  • 在 peak 位置加权聚合编码器输出，生成声学嵌入
输出：
  • pre_acoustic_embeds [B, N_token, D_enc] — 预测的声学嵌入
  • pre_token_length [B] — 预测的 token 数量
  • alphas [B, T''] — 发射概率
  • pre_peak_index — peak 位置索引
若 max(pre_token_length) < 1 → 返回空结果（静音/噪声）
pre_acoustic_embeds [B, N, D] — CIF预测的声学嵌入, pre_token_length [B] — 预测的token数量
SeACo _seaco_decode_with_ASF() — SeACo 解码 + 热词增强
SeACo（Semantic-Aware Contextual）解码，核心分为 4 步：
  1. 基础解码：Transformer Decoder 接收编码器输出 + CIF 声学嵌入 → 输出 decoder_out + decoder_hidden
    decoder_pred = log_softmax(decoder_out) [B, N, Vocab]
  2. 热词表示（_hotword_representation）：
    热词 token IDs → Decoder Embedding → 双向 LSTM 编码 → 取最后一个有效时间步的隐状态作为热词向量
    输出 selected [N_hw, D]
  3. ASF 过滤（Attention Score Filter）：
    用 seaco_decoder.forward_asf6() 计算每个热词与解码隐状态的注意力分数
    取 Top-50 热词（nfilter=50），过滤掉不相关热词，降低计算量
  4. SeACo 偏置解码：
    cif_attended = seaco_decoder(热词向量, CIF 声学嵌入)
    dec_attended = seaco_decoder(热词向量, decoder_hidden)
    merged = _merge(cif_attended, dec_attended)
    dha_pred = log_softmax(hotword_output_layer(merged)) [B, N, Vocab]
最终融合：merged_pred = decoder_pred × mask + dha_pred × (1 - mask)
mask 由 dha_pred 中的 blank token (id=8377) 决定，seaco_weight 控制融合比例（默认 0.54）
📄 asr/funasr/models/e2e_asr_paraformer.py : 1982
merged_pred [B, N_token, Vocab_size] — 融合热词偏置后的log概率分布（每个token在词表上的得分）
时间戳 calc_predictor_timestamp()（可选）
当 eable_time_stamp = True 时执行：
  • 对编码器输出做上采样（×3），重新计算细粒度的 CIF 发射概率 us_alphas 和峰值位置 us_peaks
  • 后续在 Token 后处理阶段，通过 ts_prediction_lfr6_standard(us_alphas, us_peaks, token) 将每个 token 对齐到音频时间轴
本项目 eable_time_stamp=False（use_timestamp 未配置），此步跳过。若启用，输出格式为 "0 200 你 200 400 好"（起止时间 ms + token）
📄 asr/funasr/models/e2e_asr_paraformer.py : calc_predictor_timestamp (BiCifParaformer)
阶段五 · 解码搜索
搜索 解码策略选择（三选一）
根据配置走不同解码路径：
路径A BeamSearch
当 beam_search is not None（ctc_weight≠0 或使用 LM）：
CTC-Attention 联合 BeamSearch
beam_size=10, ctc_weight=0.5
本项目配置下实际走此路径
路径B FST 热词搜索
当 eable_fst_search=True：
构建 ContextGraph
CTC prefix beam search
+ 上下文热词打分
本项目 eable_fst_search=False，不走此路径
路径C 贪心解码
当以上均不满足：
argmax(am_scores)
直接取每帧最大概率 token
最快但准确率最低
nbest_hyps: List[Hypothesis] — N-best候选序列列表（每个含token ID序列和得分）
Token Token 后处理
  • 从 hypothesis 中提取 token 序列，去除 sos/eos
  • 过滤 blank (id=0)、eos (id=2)、unk (id=1)
  • TokenIDConverter.ids2tokens()：token ID → 字符/子词 token
输出：token = ["你", "好", "萤", "石", ...]
results = [(token, hyp), ...] — token字符列表 + 假设对象（如 ["你","好","萤","石"]）
阶段六 · 文本后处理（_forward 闭包内）
拼接 sentence_postprocess(token)
将 token 列表拼接为完整文本字符串：
  • 中文 token 直接拼接（无空格）
  • 英文 token 用空格连接
  • 处理特殊符号（@@、▁ 等子词标记）
输出：text_postprocessed = "你好萤石"

将口语化数字/日期转为书面形式
例："二零二四年" → "2024年"
本项目 is_use_itn=False → 跳过此步
标点 标点恢复
Text2Punc(text, split_size=20)
为无标点文本添加逗号、句号等
本项目 punc_model_file=None → 跳过此步
asr_result_list = [{'key': 'id1', 'value': '你好萤石'}] — 最终识别结果字典列表
阶段七 · 响应封装
返回 构建响应 — 回到 EzvizModelBackend.forward()

  • 将识别文本转小写：.lower()
  • 封装为 Completion(modal="text", type="raw", data="你好萤石")
  • 写入 rsp_msg.completion 列表
  • 返回 rsp_msg → MS_Manager 框架序列化为 JSON 响应
HTTP JSON Response → 客户端

📌 本项目实际配置下的简化路径
由于 punc_model_file=None、is_use_itn=False、eable_fst_search=False，实际执行路径为：

音频 base64 解码 → PCM bytes → float32 waveform
→ FBank (80维) → LFR (560维) → CMVN 归一化
→ SANM Encoder → CIF Predictor (预测 token 数)
→ SeACo Decoder (基础解码 + LSTM 热词编码 + ASF Top50 过滤 + SeACo 偏置融合)
→ CTC-Attention BeamSearch (beam=10, ctc_weight=0.5)
→ Token ID → 字符 → sentence_postprocess 拼接
→ 文本小写 → JSON 响应

├── BeamSearch：         ~20ms
└── Token 后处理：       ~1ms
