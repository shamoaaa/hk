EzvizModelBackend.stream_forward() 流式推理流程

2-Pass 策略：流式 ParaformerOnline 实时出结果 → 结束时 SeacoParaformer 离线纠正

前置 · stream_init（仅首次调用）
初始化 stream_init() → stream_reset()
客户端调用 /stream_connect 触发。清空所有缓冲区，重置 VAD/ASR 状态：
  • data_online = bytes()，decode_beg = decode_end = 0
  • 重置流式 ASR cache（inference_online(is_final=True)）
  • 重置 VAD cache（vad_online(is_final=True)）
  • 解析热词、音频格式（pcm/opus）、唤醒帧长度、唤醒类型

客户端开始发送音频 chunk → /stream_process
阶段一 · 请求入口与音频解码
🔁 每个 chunk 调用一次 stream_forward（generator 函数，yield 返回）
入口 stream_forward(rqs_info, rsp_msg) — 入参校验
  • 检查 data_info 长度 = 1，modal = "audio"，type = "base64"
  • debug 模式下直接返回固定文本，不做推理
解码 Base64 解码 + Opus 解码（可选）
  1. base64_decode() → 二进制数据 b64Decode_Data
  2. 若 rqs_format == 'opus'：每 80 字节一帧 → opus_dec.decode(frame_size=320) → PCM 16kHz 单声道
    Opus 裸流固定 20ms 帧长，16kHz 采样率 → 每帧 320 samples
  3. 否则直接作为 PCM bytes
输出：binary_Data（PCM int16 bytes）
唤醒 唤醒帧分离 + KWS 二次验证（首帧 sequence_index=0）
仅当 audio_wakeup_type ∈ [0, 2]（主唤醒词/自定义唤醒）且 wakeup_audio_length > 0：
  • 从 binary_Data 前部截取唤醒音频 → wakeup_audio_data
  • 剩余部分作为命令音频继续处理
  • 若主唤醒词唤醒 + 业务类型启用了 KWS 过滤 + 唤醒帧 ≥ 48000 bytes（1.5s）：
    调用 kws_infer_model(wakeup_audio_data)（WeNet Conformer CTC）
    检测是否包含"你好萤石" → kws_refilter_res = True/False
唤醒类型：0=主唤醒词, 1=快捷, 2=自定义, 3=人脸, 4=点击, 5=免唤醒, 6=持续聆听
binary_Data — 命令音频 PCM bytes（已去除唤醒帧部分，int16格式）
阶段二 · 数据累积与 VAD 检测
累积 音频缓冲区追加
self.data_online += binary_Data
self.decode_end += len(binary_Data)
stride_size = 60ms × 8 chunks × 16000Hz × 2 bytes = 15360 bytes（一个解码步长）
VAD 在线 VAD 检测（按业务类型启用）
当 business_type ∈ vad_eable_type 时启用：
  1. 语义完整性调整：若上一轮有 ASR 输出，调用 semantic_complete_prob.forward(last_asr_text)（BERT 模型）
    → 动态调整 max_end_sil（500ms~1300ms）
    语义越完整 → 静音等待越短 → 更快结束
  2. FSMN VAD 推理：vad_online([binary_Data, "speech", "bytes"])
    → 返回 vadsegments：语音起止点（ms）
  3. 若检测到 起始点：记录 vad_beg_point，设置 set_vad_beg = True
  4. 若检测到 终止点：截取有效音频段，强制 is_final = True（提前结束流）
📄 asr/funasr/bin/asr_inference_paraformer_vad_tp.py : vadOnlineInfer
跳过 VAD 未启用
当 business_type ∉ vad_eable_type：
直接设置 set_vad_beg = True
不做 VAD 检测，所有音频都参与识别
is_final — 流是否结束（可能被VAD提前触发）, data_online — 累积的完整音频缓冲区（可能被VAD截断到有效语音段）
阶段三 · 2-Pass ASR 推理（核心）
判断 解码步长判断：(decode_end - decode_beg) ≥ stride_size ?
stride_size = 15360 bytes（480ms 音频）。只有累积够一个 stride 才触发流式解码。
≥ stride 累积数据足够
情况 A：is_final = False（流未结束）
Pass-1 流式推理：
inference_online(data_online[decode_beg : decode_beg+stride_size])
→ ParaformerOnline chunk 推理 → 返回中间结果
decode_beg += stride_size
情况 B：is_final = True（流结束）
Pass-2 离线纠正（需 set_vad_beg=True）：
① inference_offline(data_online) → SeacoParaformer 整段推理 → 最终纠正结果
② inference_online(data_online, is_final=True) → 重置流式 cache
stage_flag = 1（标记纠正完成）
< stride 累积数据不足
is_final = True 且 data_online > 3200 bytes（100ms）
Pass-2 离线纠正（同上）：
① inference_offline(data_online)
② inference_online(is_final=True)
stage_flag = 1
is_final = True 但 data_online ≤ 3200 bytes
音频过短，无法识别：
AudioDecodeFail 错误 → yield → return
is_final = False
数据不够一个 stride → 不做任何推理，等待下一个 chunk
asr_results_text = [{'value': '识别文本'}] — Pass-1返回中间结果(stage=0) 或 Pass-2返回纠正结果(stage=1)
阶段三补充 · Pass-1 流式模型推理细节
Pass-1 inference_online.__call__() → Speech2Text.infer()
ParaformerOnline chunk-based 流式推理，带 cache 状态：
  1. PCM → float32：load_bytes() int16 归一化
  2. WavFrontendOnline.forward()：增量 FBank 提取 + LFR + CMVN（带 cache，跨 chunk 拼接）
  3. encode_chunk()：SANM 编码器 chunk 推理，利用 cache["encoder"] 保存跨 chunk 上下文
    chunk_size = [8, 8, 4]：左看 8 帧 + 当前 8 帧 + 右看 4 帧
  4. calc_predictor_chunk()：CIF 预测器增量推理，利用 cif_hidden / cif_alphas cache
  5. cal_decoder_with_predictor_chunk()：Decoder 增量推理，利用 decode_fsmn cache
  6. 贪心解码：argmax → token → 文本拼接（中文直连，英文加空格，去 @@ 子词标记）
cache 在 stream_reset 时清零，在每个 chunk 间传递，保证流式连续性
📄 asr/funasr/bin/asr_inference_paraformer_streaming.py : 497 (inference_online) → 239 (Speech2Text.infer)
阶段四 · 声纹验证（仅 is_final 时触发）
声纹 Speaker Verification — ERes2NetV2
当 business_type ∈ sv_eable_type 且 is_final 且唤醒音频 > 1s 且命令音频 > 1s：
  1. sv_model.inference(wakeup_audio, data_online)
    → 提取两段音频的 192 维 speaker embedding → 余弦相似度 sv_result
  2. 若 sv_result ≤ sv_sim_thres（默认 0.3）→ 唤醒人与命令人不同：
    进一步计算响度差：loudness_wakeup - loudness_cmd（pyloudnorm LUFS）
    若响度差 ≥ sv_loud_thres（默认 6.5 dB）→ 清空识别结果（静默不回答）
场景：A 唤醒设备后 B 说话，且 A 声音明显更大 → 判定为误触发
📄 asr/speakerlab/bin/inference.py : speaker_verification
阶段五 · 响应封装与输出
输出 响应分支判断
✅ kws_refilter_res = True 且有识别文本
  • 累积文本：last_asr_text += value.lower()
  • 标记语义完整性待计算：semantic_complete_flag = True
  • 封装响应：stage_flag（0=中间结果, 1=纠正结果）, sequence_index, sequence_end
  • Completion(modal="text", type="raw", data="识别文本")
  • yield rsp_msg → 流式返回给客户端
  • sequence_index += 1
❌ 无识别文本 + is_final = True
yield 空响应，stage_flag=1, sequence_end=True
❌ kws_refilter_res = False（唤醒词验证失败）
yield 空响应，stage_flag=1, sequence_end=True（强制结束流）
下一个 chunk 到达 → 再次调用 stream_forward
结束 流式会话结束
当 sequence_end = True 的响应返回后，客户端停止发送。
下次新会话从 stream_init() 重新开始。

⚙️ 关键参数
chunk_size [8, 8, 4] — 左看 8 帧 + 当前 8 帧 + 右看 4 帧（每帧 60ms LFR 后）
stride_size 15360 bytes = 60ms × 8 × 16000 × 2 = 480ms 音频
vad_end_sil_init 800ms — VAD 默认静音等待阈值（可被语义完整性动态调整为 500~1300ms）
sv_sim_thres 0.3 — 声纹相似度阈值（低于此值判定非同一人）
sv_loud_thres 6.5 dB — 响度差阈值（唤醒音比命令音大 6.5dB 以上触发静默）
stage_flag 0 = Pass-1 中间结果（流式），1 = Pass-2 纠正结果（离线）
min audio for offline 3200 bytes = 100ms — 低于此长度不做离线纠正，返回错误

   原始 PCM int16          bytes              32,000 bytes (32 KB)

   识别文本                str                ~10-20 chars

━━━━ 关键决策点说明 ━━━━
  Q1-Q4: 入参与解码层 — 失败立即返回错误
  Q5:    唤醒帧处理 — 仅首帧执行，分离唤醒音用于后续 SV/KWS
  Q6:    VAD 决策 — 按业务类型启用，BERT 动态调整尾部静音
  Q7-Q9: 推理决策 — stride 累积控制流式触发，is_final 触发 Pass-2
  Q10:   声纹安全 — 双重判断（声纹+响度），过滤误唤醒
  Q11:   响应输出 — 三种分支：正常输出 / 空文本结束 / KWS失败强制结束
⚡ 流式 vs 非流式 对比
非流式 (forward) 流式 (stream_forward)
调用方式 单次 POST，完整音频 stream_init + 多次 stream_forward
模型 SeacoParaformer（一次推理） ParaformerOnline（中间）+ SeacoParaformer（纠正）
